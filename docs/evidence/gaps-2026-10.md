## Summary

The shared market-hours filter now rejects any candle whose open or close boundary touches a scheduled FX closure. Live LTF candles, live HTF candles, and R8 analysis all use it; raw provider CSVs remain byte-for-byte unchanged. Weekly closure uses Friday 17:00 through Sunday 17:00 in `America/New_York`, so the UTC boundary moves between 21:00 in US daylight time and 22:00 in standard time. December 25 and January 1 UTC holiday closure remains.

Manual and automatic scans outside the existing London/New York kill zones return `NO_TRADE` / `OUTSIDE_KILL_ZONE` before market-data fetches. A market-closed scan similarly returns before provider access. Provider provenance now distinguishes LTF and HTF in the signal ledger; failover notices include source/destination, sanitized reason, circuit states, and UTC timestamp; `/health` reports the active provider and each circuit. Finnhub and Alpha Vantage adapters and credentials were removed; active fallback order is Twelve Data → OANDA Practice → Tiingo FX.

No key or token was supplied, used, committed, or logged. This evidence is not a live-provider soak test or a profitability claim.

## G1 — same filter for live LTF/HTF and R8

`filterFxOpenMarketCandles` is applied to live LTF input and HTF input before `executeStrategyPipeline`; the R8 backtest uses the same helper. It removes intervals that open or close inside a scheduled closure, not only rows whose open instant is closed. The filter returns a new analysis array and leaves its raw input untouched.

Regression coverage added/updated in `test/market_hours.test.ts` includes closed-time pseudo-bars, exact closure boundaries, raw-array immutability, and a Monday morning synthetic scan containing weekend pseudo-bars. The Monday test compares live strategy gates, reason, and outcome to R8's matching causal decision after both use the common filter.

## G2 — DST-aware weekly closure and shared gap validation

`isScheduledMarketClosure` uses `Intl.DateTimeFormat` with `America/New_York` and local Friday/Sunday 17:00. Candle closure checks and unexplained-gap validation share `isScheduledMarketBarClosed`, so a bar touching the closure edge is treated consistently. December 25 and January 1 remain full UTC-day closures.

The regression file covers summer and winter UTC boundaries; the 2026 spring-forward and fall-back weekends; New Year adjacent weekend behavior; holiday bars; exact open/close boundaries; and a scheduled closure not being misreported as a missing-data gap.

## G3 — no scans or credits outside existing kill zones

`ScanService.scanPair` and `runAutoCycle` call the existing `classifySessionAndKillZone` from `session.ts`; outside a kill zone they return `NO_TRADE` / `OUTSIDE_KILL_ZONE` before provider fetch. No duplicate session clock or kill-zone definition was introduced. Market-closed handling remains an earlier short-circuit.

Mock regressions assert zero provider fetches in market closure and a 24-hour, 96-quarter-hour scan simulation. The latter asserts requests equal two fetches (LTF + HTF) for each eligible kill-zone window and are fewer than unrestricted two-fetch polling. A separate Monday live-vs-R8 test checks expected provider calls on an eligible in-zone scan.
